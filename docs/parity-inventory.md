# T3 Code nightly and t3term feature parity

## Scope and reading guide

This inventory compares [pingdotgg/t3code](https://github.com/pingdotgg/t3code) at tag `v0.0.46-nightly.20261007.2787` (commit `f570bd21663f56ce94c41829d3b7d72886e25a34`) with t3term at commit `a244ccd`. It was read from a shallow clone of that tag, so `.git/HEAD:1` and `.git/shallow:1` refer to that clone. Desktop citations below are relative to the T3 Code repository root; citations prefixed **term** are relative to this repository. Codex (gpt-6.1-sol) wrote it from the source, and Claude checked it: every citation resolves, the command union was recounted by hand, and every **partial** row was rechecked against t3term. Findings describe static source behavior. The app, server, and tests were not run.

t3term sends **six command types** and calls five WebSocket RPCs: `subscribeShell`, `subscribeThread`, `getTurnItem`, `dispatchCommand` and `server.getConfig`. It does not implement the desktop's project, Git, terminal, preview, file, PR, scheduling, or settings mutation APIs. Consequently, subtracting `dispatchCommand` types is only the **orchestration command gap**, not the complete desktop gap. Project mutations, for example, use `projects.mutate`, and terminal sessions use `terminal.*`. Evidence: **term** `src/client.rs:111`, `src/client.rs:238`, `src/client.rs:277`, `src/client.rs:334`, `src/client.rs:344`, `src/client.rs:356`, `src/client.rs:377`; `packages/client-runtime/src/operations/commands.ts:341`; `packages/contracts/src/rpc.ts:354`.

For feature tables, **yes** means a user can perform that feature today; **partial** names the missing behavior; **no** means no implemented user path was found in the complete Rust source scan, particularly the outbound client, CLI command enum, and TUI event handler (**term** `src/client.rs:111`, `src/main.rs:33`, `src/tui/mod.rs:728`). Seeing an event in the transcript is not equivalent to managing that feature. **port** means equivalent behavior can be built in a text UI; **approximate** names a loss; **can't** means the faithful feature needs a graphical surface, image, or browser. External launchers and textual summaries can still be useful companions to a "can't" feature. **S/M/L are research estimates**, not measured effort: S is a small action or control, M is a stateful flow or view, L is a subsystem or graphical integration. Estimates refer to bringing the listed feature to t3term, using the implementation cited in that row as the scope.
